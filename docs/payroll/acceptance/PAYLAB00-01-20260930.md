## Bounded PAYLAB00 root-cause analysis

### Local runtime configuration

The hr-suite server and browser Supabase clients both use
`NEXT_PUBLIC_SUPABASE_URL`; the existing local `.env.local` resolves to the
verified LiquidHR Core ref `wnpfloqpjvaacobppbpk`. The local test-role-switch
guard is pinned to this same ref. Only variable names and the non-secret
project host/ref were checked; no key or password value was displayed or
logged.

`loadActiveContext` obtains the authenticated user from Supabase claims, reads
that user's active tenant/HR-group and administration access rows, loads only
active Core tenants, groups and administrations, then matches the context
cookies against those current options. The cookies choose an existing option;
they do not supply an otherwise absent scope.

### Reproduction and cause

A fresh request through the existing local test-login route returned HTTP 303.
The subsequent authenticated `/dashboard/start` read failed with HTTP 500 and
PostgREST `PGRST303: JWT issued at future`. The request therefore failed while
PostgREST validated the newly issued Auth JWT, before the app could return a
fresh authenticated tenant/HR-group/administration context.

The reproducible cause is **Auth/PostgREST JWT time misalignment in the local
test environment**, not an observed application mapping bug or an empty
fixture. The earlier unmatched context IDs could not be rematched during this
failed fresh-context read; their exact prior session provenance remains
unverified. PAYLAB00 is closed as environment-gated, with no product-code fix
made solely to make acceptance pass.

## PAYLAB01 implementation

The server-only `LiquidHrPayrollSourceProvider` implements the pure
`PayrollSourceProvider` contract. It validates input, requires the existing
`salary:read` and `contract:read` permissions, compares all requested scope IDs
to the authenticated server context, and rechecks the selected confirmed
employment's tenant, HR group, administration and employee after the existing
domain-service read. It checks `PAYROLL_LAB_ENABLED` before authorization and
source reads. It uses `listEmployeeEmployments` and `getEmploymentDetail` and
contains no direct Supabase query or Core write.

### Canonical fields currently mapped

- source tenant, HR group, administration, employee and employment IDs;
- payroll period reference;
- confirmed employment start/end dates, original-hire date, seniority date,
  employment type, contract type and record status;
- salary basis/route, payment type/frequency, currency, full-time and part-time
  amounts, hourly rate and effective dates;
- average days/hours, full-time hours, part-time factor, schedule type, on-call
  flag and effective dates;
- source versions for the selected employment, salary rows and schedule rows.

Names, birth details, BSN, IBAN, email, phone and other personal profile data
are not placed in the snapshot. `sourceHash` is SHA-256 over a stable,
key-sorted serialization of source scope, period, canonical data, source
version vector and gaps. Snapshot ID and creation time are excluded.

### Explicit gaps

- `sourceIncomeRelationshipId` is `null`; IncomeRelationship is `UNSUPPORTED`
  with `CONTROL02_CONTRACT_PENDING`. Employment is not treated as an
  IncomeRelationship.
- Fiscal/tax profile is `SOURCE_GAP` with `NO_ACCEPTED_SOURCE_CONTRACT`.
- Missing, incomplete, overlapping or truncated salary/schedule histories are
  reported as `SOURCE_GAP` or `UNSUPPORTED`; they do not trigger payroll
  calculation.
- Snapshots remain in-memory; persistence belongs to PAYLAB02.
