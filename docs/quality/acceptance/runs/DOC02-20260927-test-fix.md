## 9. Fixed During Run

### DOC02-001 — Optional placeholder contract

- **Module/route:** Document Studio template editor, canonical model, generation manifest/resolver and `/document-studio/generate`.
- **Persona:** Existing seeded Test HR Admin account; all created business fixtures used synthetic Test test100.
- **Symptom / expected:** Optional placeholder input could not be authored or preserved; when absent, the resolver treated it as required and blocked generation.
- **Classification:** PRODUCT_FAILURE against the DOC02 optional-value acceptance scenario.
- **Technical root cause:** No optional attribute existed in the TypeScript canonical schema or Tiptap extensions; every manifest key was considered required. The live database canonical validator also allows only the original attribute sets.
- **Why prior tests missed it:** Existing baseline tests exercised required placeholders and unknown malformed input but had no optional flag, no duplicate optional/required occurrences, and no empty optional input.
- **What changed / fix:** Added optional metadata for known, temporal and free placeholders; Tiptap round-trip; editor toggle; manifest optional aggregation; optional blank resolution; optional generation inputs; NL/EN messages; and a localized required/empty-body error mapping. Added the forward migration to keep the SQL validator closed outside these three placeholder shapes.
- **Files/migration:** `apps/hr-suite/lib/document-studio/canonical-document.ts`, `normalized-document.ts`, `editor/tiptap-adapter.ts`, `editor/tiptap-adapter.test.ts`, `service.ts`, `labels.ts`, `components/document-studio/structured-editor.tsx`, `template-workbench.tsx`, `generation-workbench.tsx`, `app/(dashboard)/document-studio/generate/page.tsx`, `lib/document-generation/resolver.ts`, `service.ts`, `messages/nl/documentStudio.json`, `messages/en/documentStudio.json`, and `supabase/migrations/20260927080748_document_studio_optional_placeholders.sql`.
- **DEV data/config changed:** Yes. The one explicitly approved migration and synthetic DOC02 template/component/generation/Storage/Dossier records were created. No Auth user, role, permission, RLS, grant or module configuration was changed.
- **Regression / retest:** DOC02 synthetic exact-output tests, resolver, canonical, manifest, Tiptap, live SQL runtime probes and authenticated HR Admin optional-blank generation; full run 462/462 files and 1,844/1,844 tests passed.
- **Downstream rechecked:** Document Studio/Generation tests, full HR-suite, strict TypeScript, ESLint, i18n and production build.
- **Security/privacy impact:** No permissions, RLS, roles, audiences or grants changed. Remote readback confirms the existing validator signature, `SECURITY DEFINER` and `search_path = pg_catalog`. The broader persona matrix remains blocked/incomplete as detailed above.
- **Restoration vs new behavior:** Implements the requested optional-value behavior while preserving required-by-default semantics; no new audience or access capability.
- **Commit SHA:** None; no commit created because the run is BLOCKED. Candidate HEAD remains the baseline SHA.
- **Prevention lesson:** Keep the TypeScript canonical parser and database canonical validator in sync whenever a persisted document attribute is added.
