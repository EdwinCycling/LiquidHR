## APIAI-06 implementation

The implementation is confined to the branch above and adds a shared `Prepare → Preview → Confirm → Execute → Readback` service for two existing Talent writes:

1. `talent.development-goal.create` through `createTalentGoal`.
2. `talent.goal-check-in.create` through `createTalentGoalCheckIn`.

The service revalidates existing domain permissions and HERA/TALENT module access at each stage; binds the server preview hash to tenant, actor, HR group, administration, active roles, permissions, payload and preview; expires drafts after 15 minutes; uses an idempotency key and compare-and-set version/status checks; and never retries an unknown domain-write outcome. Errors are bounded, correlation IDs persist, and readback is scope-limited. Manager goal creation additionally verifies current active direct-report placement in the selected HR group/administration; Employee actions are self-bound; HR Admin scope uses the active tenant/HR-group/administration context.

HeRa calls the shared service through authenticated internal routes, with distinct confirm and execute requests. Local MCP exposes the same lifecycle behind its existing local-only/fail-closed gate. ChatGPT MCP metadata remains read-only. Existing Talent service functions remain the only business-write path.

The migration extends the existing allowlists, retains owner reads and legacy draft policies, denies authenticated direct writes to the controlled action types, grants the existing server-only service role the required storage operations, and writes minimal lifecycle events to existing `audit_logs` through a revoked private trigger. The admin client is called only in the server-only controlled-action service after authorization; the conversation owner is checked with the regular RLS client first. No action payload/body is copied into audit JSON.
