## PDF, asset and authorization checks

- The old DG1 test used `TextDecoder` and PDF-internal regexes, which are brittle for compressed streams. PDF.js and pdf-lib also reproduced a real blank-PDF defect on unchanged main `8c585f8`: Chromium returned two pages with empty content streams and no fonts because CSS `data:` font URLs reported network errors. The renderer now registers the three existing Work Sans files through `FontFace`, awaits their load, and fails closed unless all three report `loaded`.
- The updated test parses generated bytes with PDF.js and pdf-lib. It checks A4 bounds, in-page positioned text, multiple pages, all 80 fixture lines, embedded non-empty `FontFile2`/`FontFile3` data for Work Sans 400 normal, 400 italic and 700 normal, and identical normalized hashes across two renders. The representative fixture parsed as three A4 pages.
- The PAYRUN01 PDF test uses the default local LiquidHR brand asset and confirms its generated PDF contains a non-empty embedded image XObject. The Vercel trace checker independently verifies that `logo-horizontal.png` and the used Work Sans files are packaged on the appropriate renderer routes.
- Focused runtime/security run: **45/45 tests across 8 files passed**. This includes Document Studio PDF, Payroll Lab validation PDF and its 12 authorization tests, PAYRUN01 preview authorization/scope, stored artifact route/service, payslip PDF and distribution read-scope tests.
- Linux production build: **PASS** with a 4 GiB Node heap. It completed TypeScript, static generation, payroll client-boundary check, exact trace preparation and size/asset validation. The standalone type-check at the sandbox default 2 GiB heap ran out of memory; the production build's TypeScript phase passed.
