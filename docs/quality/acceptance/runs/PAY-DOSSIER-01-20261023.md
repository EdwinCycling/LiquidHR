## R1 payroll and document flow

The isolated flow proves:

1. Repeating the same R1 calculation returns the same CONCEPT run; only one run is stored.
2. Before finalization, Employee salary statements and payroll payslip periods are empty, and PDF creation is rejected.
3. The Payroll service accepts review and finalization only in the explicitly enabled isolated test scenario.
4. The finalized PDF is visibly marked **TEST / NIET VOOR UITBETALING** and parsed from its generated PDF bytes. Its provenance binds the source hash, calculation result hash, finalized event, document classification, and PDF hash.
5. Repeating artifact creation returns the same artifact ID and hash; the isolated store contains one artifact. Test triggers reject artifact or lifecycle mutation.
6. Employee and HR Admin reads return identical saved PDF bytes and SHA-256. Employee response is inline; HR Admin download is an attachment. Both response hashes equal the stored artifact hash.

The product already links payroll artifacts into the employee payslip surface: `/my-salary` and Employee Detail's `payslips` tab list finalized payroll periods and open the payroll artifact route. The employee-detail tab keeps imported payslips and Payroll artifacts as separate linked sources; it does not copy the Payroll PDF into the generic document index. HR Admin opens the same stored Payroll artifact through the employee payroll-payslip route.

The test exercises the existing services and shared response helper against isolated dependencies. Existing authorization tests cover self-only salary reads and deny cross-employee and mismatched tenant/HR-group/administration access. A live authenticated browser session was not used, so actual signed-in Employee and HR Admin rendering/download remains an external acceptance check.
